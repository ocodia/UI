UI documentation

UI is a complete UI system in development, built around native HTML and optional light-DOM custom elements. Begin with shipped features; consult the catalogue before using any proposed element.

Every guide below is available as a rendered page in the documentation site. Browse the component sidebar or use the component searcher to find a specific control. Shipped component pages combine examples, inspectable code, native API tables and verification limits. Resize an example with its edge handle or width control to test actual viewport behavior.

Use UI

  1. Getting started: files, page structure, enhancement and examples.
  2. Current API: exact layouts, CSS variables, forms and summary methods available today.
  3. Theming: token layers, light/dark brands, scope and verification.
  4. UI conventions: navigation, commands, content, choices and feedback.
  5. Component catalogue: every reference component, UI approach, phase and acceptance work.

Buttons and control sizes documents the implemented data-variant and data-size attributes, native semantics and theme variables.

Form integration covers external/dynamic ownership, checkbox/radio questions, localization and application-owned asynchronous submission.

Density documents comfortable/compact composition, nested scopes and independent control sizes.

Native dialog covers modal opening/closing, focus, forms, lifecycle and support-failure fallback.

The native-value recipe combines grouped errors with date, time, file and range inputs. Read the native-input integration contract for serialized values and server responsibilities.

The survey briefing demonstrates nested panels, named scroll regions and native multiple selection. Its composition contract explains reading order, keyboard access, repeated values and reset.

Build UI

Read architecture before implementation. Use the component template to define behavior before adding code. Follow contributing and the accessibility contract. The roadmap defines sequence and dependencies, not release dates.

To change this site, read documentation authoring. The pages use UI's own layouts, native controls and disclosures. Guide content, examples and code drawers remain readable without the documentation script.

Understand status

  • Native recipe: an existing HTML primitive styled by UI. It does not promise all features of another library's component.
  • Foundation: an existing UI composition primitive used as the starting point for that component.
  • Planned: no implementation is promised; names, attributes and methods are proposals.
  • Release readiness: tracked separately through evidence. Native/foundation does not mean audited or stable v1.

The JSON field values are native, foundation, and planned. components.json is the scope inventory; components.md and the browser explorer are generated views of it.
