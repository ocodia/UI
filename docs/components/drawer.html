Drawer

ui-drawer around native dialogFoundationPhase 2

Modal viewport-edge task with native dialog ownership, single-copy inline fallback and four logical placements. Non-modal panels are outside this implementation.

Implementation maturity: experimental. See dated evidence and remaining release gates.

Read the component specification and its Markdown source.

Visit note with failure and retry

Native form values and linked validation, with application-owned pending/failure/retry feedback. Without script the GET destination is an unsaved example page.

Full widthDrag the edge or use arrow keys; Shift changes by 50px. Home/End use minimum/full width.
Code
<script src="js/ui.js" defer></script>
<section aria-labelledby="survey-task">
  <h2 id="survey-task" tabindex="-1">Survey arrangements</h2>
  <p>Read the briefing before travelling. Opening or closing it sends nothing.</p>
  <ui-drawer data-placement="inline-start">
    <button type="button" data-ui-open="survey-drawer" hidden>Read survey briefing</button>
    <dialog id="survey-drawer" open aria-labelledby="survey-drawer-title" data-ui-return-focus="survey-task">
      <h3 id="survey-drawer-title" tabindex="-1" data-ui-focus>Survey briefing</h3>
      <button type="button" data-ui-close hidden>Close briefing</button>
      <p>This local preview sends nothing while scripts run. The first attempt demonstrates a recoverable failure; retry succeeds. Closing cancels pending preview work and preserves your answers.</p>
      <ui-form>
        <form id="drawer-form" action="../../examples/drawer.html" method="get">
          <ui-error-summary hidden><h2>There is a problem</h2><ul></ul></ui-error-summary>
          <ui-field><label for="drawer-note">Visit note</label><input id="drawer-note" name="note" required autocomplete="off"></ui-field>
          <button type="submit" name="action" value="preview">Preview note</button>
          <button type="reset">Reset note</button>
          <p id="drawer-status" role="status"></p>
        </form>
      </ui-form>
      <form method="dialog"><button type="submit" value="finished" hidden>Finish reading</button></form>
    </dialog>
  </ui-drawer>
  <a id="after-drawer" href="../../examples/index.html">More UI examples</a>
</section>
<script>
(() => {
  const form = document.querySelector('#drawer-form'), dialog = form.closest('dialog');
  const status = form.querySelector('[role="status"]');
  let generation = 0, attempts = 0, timer;
  const cancel = () => { generation++; clearTimeout(timer); form.removeAttribute('aria-busy'); };
  form.addEventListener('submit', event => {
    event.preventDefault(); cancel();
    const request = generation, note = new FormData(form, event.submitter).get('note');
    attempts++; status.textContent = 'Preparing preview…'; form.setAttribute('aria-busy', 'true');
    // Keep the focused submitter usable; request generations reject superseded attempts.
    timer = setTimeout(() => {
      if (generation !== request || !form.isConnected || !dialog.open) return;
      form.removeAttribute('aria-busy');
      status.textContent = attempts === 1 ? 'Preview failed. Your note is unchanged. Select Preview note to retry.' : 'Preview ready: ' + note + '. Nothing was saved or sent.';
    }, 300);
  });
  form.addEventListener('reset', event => { queueMicrotask(() => { if (!event.defaultPrevented) { cancel(); attempts = 0; status.textContent = ''; } }); });
  dialog.addEventListener('close', () => { cancel(); status.textContent = ''; });
})();
</script>

Keyboard, focus & native state

Use native children for semantics and interaction. Layout wrappers add no keyboard behavior or implicit roles. Keep visual order consistent with DOM reading order, including in RTL.

Values, validation & fallback

This primitive does not own application values, persistence or transport. Native descendants retain labels, values and form associations. Keep content readable before optional application behavior initializes.

Keep labels and instructions available when JavaScript fails. Applications own async work, recovery and server validation. Test disabled, invalid, long-content and loading states where the task supports them.

API & styling

SurfaceContract
ui-drawerModal-only native dialog ownership; initializes by element name with no registration.
data-placementinline-end by default; inline-start, block-start and block-end are supported.
Focus / dismissaldata-ui-focus initial target, data-ui-return-focus survivor, native Escape and explicit close.
Native state / lifecycledialog.open/:modal; UI.enhance/UI.destroy refresh and cleanup to inline fallback.
CSS variables--ui-drawer-size: 24rem; --ui-drawer-padding: var(--ui-space-5).

Use the implemented drawer contract for the full integration rules and supported cases. Native attributes retain their standard meanings. Only ui-form and ui-error-summary register behavior.

Styles come from css/ui.css in the ui layer. Geometry and semantic colors use UI theme variables. Density and control sizes have separate scopes; they do not apply to every element.

Verification & known limits

Native modality/Escape, initial and return focus, four logical edges/RTL, long-content scrolling, native forms, nested help, lifecycle/failure recovery, reduced motion and platform evidence.

Native/foundation is an implementation route, not a stable-release or accessibility certification. See dated results and unresolved findings; run the browser checks. Manual platform and assistive-technology verification remains part of release readiness.
