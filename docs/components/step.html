Components / Navigation

Step

native li inside ui-steps > olFoundationPhase 2

CSS-only ordered task stages. Author current location with aria-current=step and completed/error/future status as visible text. Real links only for reachable stages; applications own validation, persistence, progression and focus. See docs/stepper.md.

Implementation maturity: experimental. See dated evidence and remaining release gates.

Read the component specification and its Markdown source.

Keyboard, focus & native state

Native ordered steps with optional real links. Tab/Shift+Tab reaches only links; Enter navigates normally. Plain future/current text is not a focus stop. No composite roles, roving focus or progression handler.

Values, validation & fallback

CSS-only ui-steps scopes an ordered list; each step is a native li. Author aria-current=step on the current item and completed/error status as text. Applications own validation, saving, permissions, current location and focus after transitions.

Keep labels and instructions available when JavaScript fails. Applications own async work, recovery and server validation. Test disabled, invalid, long-content and loading states where the task supports them.

API & styling

SurfaceContract
ui-steps / ol / liCSS-only ordered composition; Step is a native li.
aria-current=stepAuthor on one current li; omit after completion. Independent of visible completed/error text.
Reachable stagesNative anchors with real task URLs. Unavailable stages are plain text, with an explanation.
Native numberingOrdered list markers and authored start/value semantics stay native. No CSS-generated numbers or statuses.

Use the implemented stepper contract for the full integration rules and supported cases. Native attributes retain their standard meanings. Only ui-form and ui-error-summary register behavior.

Styles come from css/ui.css in the ui layer. Geometry and semantic colors use UI theme variables. Density and control sizes have separate scopes; they do not apply to every element.

Verification & known limits

Verify native order/numbering, current/completed/error text, reachable real URLs, no-script task-heading navigation, native form ownership, nested lists and narrow RTL/zoomed-text layouts. Dated evidence and open platform release work are in ACCESSIBILITY.md.

Native/foundation is an implementation route, not a stable-release or accessibility certification. See dated results and unresolved findings; run the browser checks. Manual platform and assistive-technology verification remains part of release readiness.
