Components / Actions

Button

button; a[href]Native recipePhase 1

Buttons perform actions. Use their emphasis and size to make the next step clear while keeping native activation, submission and reset behavior.

Examples

Action variants

These appearance samples do not perform project operations.

</ui-cluster>

Keyboard, focus & native state

Native buttons activate with Enter/Space and remain separate Tab stops. Use anchors for navigation and explicit button types for operations. Disabled controls cannot activate. Busy feedback and duplicate-operation handling belong to the application.

Values, validation & fallback

Preserve submit/reset, native submitter name/value, form ownership and formnovalidate. A button inside a form defaults to submit. data-variant and data-size affect CSS presentation only; unknown values use defaults.

Keep labels and instructions available when JavaScript fails. Applications own async work, recovery and server validation. Test disabled, invalid, long-content and loading states where the task supports them.

See the native family state audit for default, long-content, disabled/read-only, invalid, busy and fallback coverage, including states that do not apply.

API & styling

SurfaceContract
typesubmit, reset or button. Inside a form the default is submit.
disabledNative Boolean disabled state; aria-disabled alone does not prevent activation.
name / value / formPreserve native submitter identity, successful value and external form association.
formnovalidateA submitter may bypass validation for its own submission.
data-variantprimary (default), secondary, quiet or danger. Unknown values use primary.
data-sizesmall, default or large. Minimum geometry remains content-sensitive.

Use the implemented controls contract for the full integration rules and supported cases. Native attributes retain their standard meanings. Only ui-form and ui-error-summary register behavior.

Styles come from css/ui.css in the ui layer. Geometry and semantic colors use UI theme variables. Density and control sizes have separate scopes; they do not apply to every element.

Catalogue markup

This minimal structure describes the route. Live examples above add the context needed to try it.

Minimal markup
<button type="submit">Save project</button>
<button type="reset" data-variant="secondary">Reset answers</button>
<button type="button" data-variant="quiet" data-size="small">Clear filters</button>

Verification & known limits

Enter/Space, focus, submitter, loading feedback, and disabled behavior.

Native/foundation is an implementation route, not a stable-release or accessibility certification. See dated results and unresolved findings; run the browser checks. Manual platform and assistive-technology verification remains part of release readiness.
