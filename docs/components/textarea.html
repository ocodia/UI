Components / Forms

Textarea

textarea inside ui-fieldNative recipePhase 1

Collect multiline text with native editing, selection and resizing. Give longer answers room and describe any limits before entry.

Examples

Multiline text and reset

Newlines stay in the native value. Keep native resizing available.

Full widthDrag the edge or use arrow keys; Shift changes by 50px. Home/End use minimum/full width.
Code
<script src="js/ui.js" defer></script>
<form>
  <label for="notes">Field notes</label>
  <textarea id="notes" name="notes" rows="4" maxlength="500">Shoreline observations</textarea>
  <ui-cluster><button type="submit">Inspect notes</button><button type="reset" data-variant="secondary">Reset</button></ui-cluster>
</form>

Open example on its own · Form previews send nothing.

Read-only and disabled

Read-only text remains successful; disabled text is omitted. Native selection and copying stay available on the read-only answer.

Full widthDrag the edge or use arrow keys; Shift changes by 50px. Home/End use minimum/full width.
Code
<script src="js/ui.js" defer></script>
<form>
  <ui-field><label for="original">Original notes (read-only)</label><textarea id="original" name="retained" readonly>Keep the original field observations.</textarea></ui-field>
  <ui-field><label for="archived">Archived notes (unavailable)</label><textarea id="archived" name="omitted" disabled>Editing unavailable.</textarea></ui-field>
  <button type="submit">Inspect values</button>
</form>

Open example on its own · Form previews send nothing.

Required notes and error recovery

Submit without notes to see recovery. Native resizing remains available; maxlength does not replace a server limit.

Full widthDrag the edge or use arrow keys; Shift changes by 50px. Home/End use minimum/full width.
Code
<script src="js/ui.js" defer></script>
<ui-form>
  <form>
    <ui-field>
      <label for="notes">Describe access needs and meeting arrangements for the whole research team</label>
      <ui-hint id="notes-hint">Enter notes, up to 500 characters. Keep private details out of this demonstration.</ui-hint>
      <textarea id="notes" name="notes" rows="4" maxlength="500" required aria-describedby="notes-hint"></textarea>
    </ui-field>
    <ui-cluster><button type="submit">Check notes</button><button type="reset" data-variant="secondary">Reset</button></ui-cluster>
  </form>
</ui-form>

Open example on its own · Form previews send nothing.

Keyboard, focus & native state

Use a visible label and explain a meaningful length limit. Native multiline editing, selection, paste and resize stay available. Do not make the field a single-line input.

Values, validation & fallback

Name/value remain native; newlines are preserved. Rows is initial geometry, not a length limit. Maxlength is a client constraint; the server rechecks it. Readonly values serialize; disabled values do not.

Keep labels and instructions available when JavaScript fails. Applications own async work, recovery and server validation. Test disabled, invalid, long-content and loading states where the task supports them.

See the native family state audit for default, long-content, disabled/read-only, invalid, busy and fallback coverage, including states that do not apply.

API & styling

SurfaceContract
name / valueUse a meaningful form key and answer. An enabled successful native control contributes its value.
disabledBoolean presence disables interaction and excludes the control from form submission.
requiredWhere supported, the native control must satisfy its missing-value constraint before submission.
formAssociate with a native form by ID when outside its subtree. Labels and DOM layout stay independent of ownership.
aria-describedbySpace-separated hint/error IDs. Preserve existing descriptions when adding feedback.
rows / colsNative initial geometry. CSS and resizing may change the rendered area.
minlength / maxlengthText length constraints; rows does not limit the answer length.
readonlyKeeps the answer selectable and successful while preventing edits.
data-sizesmall, default or large styling with multiline behavior preserved.

Use the implemented forms contract for the full integration rules and supported cases. Native attributes retain their standard meanings. Only ui-form and ui-error-summary register behavior.

Styles come from css/ui.css in the ui layer. Geometry and semantic colors use UI theme variables. Density and control sizes have separate scopes; they do not apply to every element.

Verification & known limits

Newlines, paste, zoom, error recovery, read-only, disabled, and reset.

Native/foundation is an implementation route, not a stable-release or accessibility certification. See dated results and unresolved findings; run the browser checks. Manual platform and assistive-technology verification remains part of release readiness.
