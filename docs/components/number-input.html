Components / Forms

Number Input

input[type=number]Native recipePhase 1

Collect a quantity with native numeric editing and explicit bounds. Use a text input for identifiers that happen to contain digits.

Examples

Native entry and serialized values

The preview reports FormData locally. The server must validate submitted values; browser presentation varies by locale and platform.

Full widthDrag the edge or use arrow keys; Shift changes by 50px. Home/End use minimum/full width.
Code
<form>
  <ui-field><label for="answer">Number of copies</label><input id="answer" name="answer" type="number" min="1" max="20" step="1" value="1"></ui-field>
  <ui-cluster><button type="submit">Inspect values</button><button type="reset" data-variant="secondary">Reset</button></ui-cluster>
</form>

Open example on its own · Form previews send nothing.

Read-only and disabled

Read-only answers retain their values and serialize; disabled answers are omitted. These modes do not participate in constraint validation.

Full widthDrag the edge or use arrow keys; Shift changes by 50px. Home/End use minimum/full width.
Code
<form>
  <ui-field><label for="readonly">Number of printed field guides for the whole research team (read-only)</label><input id="readonly" name="retained" type="number" value="4" readonly></ui-field>
  <ui-field><label for="disabled">Number of printed field guides for the whole research team (unavailable)</label><input id="disabled" name="omitted" type="number" value="4" disabled></ui-field>
  <button type="submit">Inspect values</button>
</form>

Open example on its own · Form previews send nothing.

Required answer and constraint recovery

Submit an empty or out-of-bounds answer to see linked error recovery. Native validity and normalized values remain on the input; the server must recheck constraints.

Full widthDrag the edge or use arrow keys; Shift changes by 50px. Home/End use minimum/full width.
Code
<ui-form>
  <form>
    <ui-field>
      <label for="answer">Number of printed field guides for the whole research team</label>
      <ui-hint id="answer-hint">Enter an even number from 2 to 20.</ui-hint>
      <input id="answer" name="answer" type="number" min="2" max="20" step="2" required aria-describedby="answer-hint">
    </ui-field>
    <ui-cluster><button type="submit">Check answer</button><button type="reset" data-variant="secondary">Reset</button></ui-cluster>
  </form>
</ui-form>

Open example on its own · Form previews send nothing.

Keyboard, focus & native state

Use number for quantities, not account IDs or postal codes. The browser supplies numeric editing and step controls. Explain units and bounds in text.

Values, validation & fallback

Min/max/step constrain a numeric answer; required separately controls emptiness. Locale editing varies. The value is a string for FormData; validate and convert deliberately on the server.

Keep labels and instructions available when JavaScript fails. Applications own async work, recovery and server validation. Test disabled, invalid, long-content and loading states where the task supports them.

See the native family state audit for default, long-content, disabled/read-only, invalid, busy and fallback coverage, including states that do not apply.

API & styling

SurfaceContract
name / valueUse a meaningful form key and answer. An enabled successful native control contributes its value.
disabledBoolean presence disables interaction and excludes the control from form submission.
requiredWhere supported, the native control must satisfy its missing-value constraint before submission.
formAssociate with a native form by ID when outside its subtree. Labels and DOM layout stay independent of ownership.
aria-describedbySpace-separated hint/error IDs. Preserve existing descriptions when adding feedback.
min / max / stepNumeric constraints. Default step is 1; use step="any" when arbitrary fractional values are appropriate.
valueAsNumberNative numeric property; can be NaN when there is no usable number.
readonlyPrevents editing; unlike disabled, it does not omit the value.

Use the implemented forms contract for the full integration rules and supported cases. Native attributes retain their standard meanings. Only ui-form and ui-error-summary register behavior.

Styles come from css/ui.css in the ui layer. Geometry and semantic colors use UI theme variables. Density and control sizes have separate scopes; they do not apply to every element.

Catalogue markup

This minimal structure describes the route. Live examples above add the context needed to try it.

Minimal markup
<label for="quantity">Quantity</label>
<input id="quantity" name="quantity" type="number" min="1" step="1" value="1">

Verification & known limits

Keyboard stepping, decimals, invalid entry, wheel interaction, labels, and reset.

Native/foundation is an implementation route, not a stable-release or accessibility certification. See dated results and unresolved findings; run the browser checks. Manual platform and assistive-technology verification remains part of release readiness.
