Dialog

dialog with showModal()Native recipePhase 1

Present a focused modal task using the native dialog. The browser supplies modality; application code chooses the opening, closing and recovery policy.

Shared UI setup

Load js/ui.js once. Use the shared enhancement API for standard setup and scoped cleanup; application business rules remain separate.

Declarative native dialog

One readable native dialog supplies the no-script baseline. ui.js installs opening, closing, initial focus and fallback; no application initialization script is required.

Full widthDrag the edge or use arrow keys; Shift changes by 50px. Home/End use minimum/full width.
Code
<script src="js/ui.js" defer></script>
<section>
  <h2 id="enhance-task" tabindex="-1">Survey arrangements</h2>
  <p>Read the briefing before travelling. Opening or closing it sends nothing.</p>
  <button id="enhance-open" type="button" data-ui-open="enhance-dialog" hidden>Open survey briefing</button>
  <dialog id="enhance-dialog" open data-ui="dialog" aria-labelledby="enhance-title" data-ui-return-focus="enhance-task">
    <h3 id="enhance-title" tabindex="-1" data-ui-focus>Survey briefing</h3>
    <button type="button" data-ui-close hidden>Close survey briefing</button>
    <p>Meet at the visitor centre at 09:30. Keep your existing observations and choose the route that suits your access needs.</p>
    <h4>Before the visit</h4>
    <p>Keep the reference with your field notes. Bring water and a way to record observations. Read the complete route description before leaving home.</p>
    <p><a href="../forms.html">Read about native form values</a>.</p>
    <button type="button" data-ui-close hidden>Close survey briefing</button>
  </dialog>
</section>

Examples

Modal task with inline fallback

This short sample demonstrates native modality. The full recipe documents trigger removal, lifecycle and async ownership.

Full widthDrag the edge or use arrow keys; Shift changes by 50px. Home/End use minimum/full width.
Code
<script src="js/ui.js" defer></script>
<section aria-labelledby="task-title">
  <h2 id="task-title" tabindex="-1">Project information</h2>
  <button id="open-dialog" type="button" hidden>Open information</button>
  <p id="fallback">Opening information sends nothing. Your answers stay on this page.</p>
  <dialog id="information" aria-labelledby="information-title" hidden><h2 id="information-title">Project information</h2><p>Opening information sends nothing. Your answers stay on this page.</p><form method="dialog"><button value="close" autofocus>Close information</button></form></dialog>
</section>
<script>
const dialog = document.querySelector('#information');
const opener = document.querySelector('#open-dialog');
const fallback = document.querySelector('#fallback');
if (typeof dialog.showModal === 'function' && typeof dialog.close === 'function') {
  opener.addEventListener('click', () => {
    if (dialog.open) return;
    opener.focus();
    dialog.returnValue = '';
    try { dialog.showModal(); if (dialog.open) return; } catch {}
    fallback.hidden = false; opener.hidden = true; dialog.hidden = true;
    document.querySelector('#task-title').focus();
  });
  dialog.hidden = false; fallback.hidden = true; opener.hidden = false;
}
</script>

<script>
(() => {
  const dialog = document.querySelector('#briefing-dialog');
  const opener = document.querySelector('#briefing-open');
  const fallback = document.querySelector('#briefing-fallback');
  const heading = document.querySelector('#briefing-task-title');
  if (!dialog || !opener || !fallback || !heading || typeof dialog.showModal !== 'function' || typeof dialog.close !== 'function') return;
  opener.addEventListener('click', () => {
    if (dialog.open) return;
    opener.focus();
    dialog.returnValue = '';
    try {
      dialog.showModal();
      if (dialog.open) {
        dialog.scrollTop = 0;
        return;
      }

    opener.hidden = true;
    fallback.hidden = false;
    fallback.querySelector('h2').focus();
  });
  dialog.addEventListener('close', () => {
    if (!dialog.open && (!opener.isConnected || opener.disabled || opener.hidden)) heading.focus();
  });
  dialog.hidden = false;
  fallback.hidden = true;
  opener.hidden = false;
})();
</script>

Keyboard, focus & native state

The browser owns modal focus containment and inertness after showModal(). Choose initial focus, an explicit close action, Escape policy and a logical return target. The complete dialog guide covers these decisions and support failure.

Values, validation & fallback

A method=dialog form closes without network submission. Clear returnValue before opening; dismissal must not reuse a previous result. Closing is separate from resetting answers or saving data. Do not nest forms.

Keep labels and instructions available when JavaScript fails. Applications own async work, recovery and server validation. Test disabled, invalid, long-content and loading states where the task supports them.

See the native family state audit for default, long-content, disabled/read-only, invalid, busy and fallback coverage, including states that do not apply.

API & styling

SurfaceContract
showModal()Native method that opens a modal and makes the surrounding document inert.
close(result)Native method to close and optionally set the result string.
returnValueResult string. Clear it before each opening so dismissal cannot reuse stale confirmation.
cancelCancelable native dismissal request. The recipe leaves it uncancelled.
closeNative close notification; use it for task completion/focus recovery when necessary.

Use the implemented dialog contract for the full integration rules and supported cases. Native attributes retain their standard meanings. Only ui-form and ui-error-summary register behavior.

Styles come from css/ui.css in the ui layer. Geometry and semantic colors use UI theme variables. Density and control sizes have separate scopes; they do not apply to every element.

Verification & known limits

Browser assertions cover short/long modal focus, scroll bounds, both close actions, reopening at the start, background focus blocking, close results, return focus after trigger changes and unsupported/open-failure/no-script fallback. Verify remaining browser/mobile, zoom, forced colors, touch and screen-reader combinations before release; see dated manual evidence in ACCESSIBILITY.md.

Native/foundation is an implementation route, not a stable-release or accessibility certification. See dated results and unresolved findings; run the browser checks. Manual platform and assistive-technology verification remains part of release readiness.
