Tab Group

ui-tabs and ui-tablist around links and sectionsFoundationPhase 2

Experimental ui-tabs enhancement of linked sections with a named ui-tablist through js/ui.js, opted into by element name without a data-ui marker. Manual activation by default, optional eager automatic activation and horizontal/vertical navigation; see docs/tabs.md.

Implementation maturity: experimental. See dated evidence and remaining release gates.

Read the component specification and its Markdown source.

Examples

Visit information with manual activation

Full widthDrag the edge or use arrow keys; Shift changes by 50px. Home/End use minimum/full width.
Code
<script src="js/ui.js" defer></script>
<section aria-labelledby="visit-title">
  <h2 id="visit-title">Plan your visit</h2>
  <p>Use Left/Right or Home/End to move between tabs, then Enter or Space to show the panel. <a href="#visit-equipment-note">Jump to equipment</a>.</p>
  <ui-tabs id="visit">
    <ui-tablist aria-label="Visit information">
      <a id="visit-arrival-tab" href="#visit-arrival">Getting here</a>
      <a id="visit-equipment-tab" href="#visit-equipment">What to bring when the weather changes during a long coastal visit</a>
      <a id="visit-access-tab" href="#visit-access">Accessibility arrangements</a>
    </ui-tablist>
    <section id="visit-arrival" aria-labelledby="arrival-title"><h3 id="arrival-title">Getting here</h3><p>Meet at the visitor centre at 09:30.</p><a href="../../docs/forms.html">Read the preparation guide</a></section>
    <section id="visit-equipment" aria-labelledby="equipment-title"><h3 id="equipment-title">What to bring</h3><p id="visit-equipment-note">Bring waterproof clothing, drinking water and your field notebook.</p></section>
    <section id="visit-access" aria-labelledby="access-title"><h3 id="access-title">Accessibility arrangements</h3><p>Contact the coordinator before the visit to discuss step-free routes and rest stops.</p></section>
  </ui-tabs>
</section>

Vertical tabs with automatic activation

Both panels are already available. Up/Down moves focus and selection together.

Full widthDrag the edge or use arrow keys; Shift changes by 50px. Home/End use minimum/full width.
Code
<script src="js/ui.js" defer></script>
<ui-tabs data-activation="automatic" data-orientation="vertical">
  <ui-tablist aria-label="Route information"><a id="coast-tab" href="#coast">Coast</a><a id="woodland-tab" href="#woodland">Woodland</a></ui-tablist>
  <section id="coast"><h2>Coastal route</h2><p>Allow three hours and check the tide before departure.</p></section>
  <section id="woodland"><h2>Woodland route</h2><p>Allow two hours. The path can be muddy.</p></section>
</ui-tabs>

Nested tabs, disclosures and form errors

Error links reveal the field before focusing it. Reset preserves the selected view.

Full widthDrag the edge or use arrow keys; Shift changes by 50px. Home/End use minimum/full width.
Code
<script src="js/ui.js" defer></script>
<ui-form><form>
  <h2>Visit notes</h2><p>Check this local draft to inspect errors. Nothing is saved.</p>
  <ui-tabs>
    <ui-tablist aria-label="Visit notes"><a id="observation-tab" href="#observation-panel">Observation</a><a id="context-tab" href="#context-panel">Context</a></ui-tablist>
    <section id="observation-panel"><h3>Observation</h3><label for="observation">Observation title</label><input id="observation" name="observation" value="Tide pools" required></section>
    <section id="context-panel"><h3>Context</h3>
      <ui-accordion data-ui="accordion"><details><summary>Field context</summary><ui-field><label for="context">Field context</label><input id="context" name="context" required><ui-error hidden>Error: Enter field context</ui-error></ui-field>
        <ui-tabs><ui-tablist aria-label="Reference"><a id="reference-tab" href="#reference-panel">Reference</a><a id="status-tab" href="#status-panel">Status</a></ui-tablist>
          <section id="reference-panel"><h4>Original reference</h4><label for="reference">Reference (read-only)</label><input id="reference" name="reference" value="COAST-01" readonly></section>
          <section id="status-panel"><h4>Draft status</h4><p role="status">No files uploaded. Upload is unavailable in this local draft.</p><label for="upload">Upload unavailable</label><input id="upload" type="file" disabled></section>
        </ui-tabs>
      </details></ui-accordion>
    </section>
  </ui-tabs>
  <ui-cluster><button type="submit">Check draft</button><button type="reset">Reset draft</button></ui-cluster>
</form></ui-form>

Keyboard, focus & native state

Arrow keys and Home/End move within the list; Enter/Space activates in default manual mode. Automatic activation and vertical orientation are explicit alternatives. Tab leaves the list for the selected panel. RTL reverses horizontal arrows.

Values, validation & fallback

Readable fragment links and sections are the baseline. UI coordinates selection, fragment and form-error reveal without changing native values. Late pairs require explicit enhance; destroy restores all sections. Read the Tabs guide for validation and lifecycle limits.

Keep labels and instructions available when JavaScript fails. Applications own async work, recovery and server validation. Test disabled, invalid, long-content and loading states where the task supports them.

API & styling

SurfaceContract
ui-tabsThe element name opts in around one named ui-tablist and paired native fragment links/sections. No data-ui marker or new registration; legacy data-ui="tabs" remains compatible.
ui-tablistRequired direct structural child containing native anchors. Parent owns its role and keyboard behavior; legacy div[data-ui-tablist] remains compatible.
data-activationmanual by default; automatic only for immediately available panels. Invalid values use manual.
data-orientationhorizontal by default, or vertical; invalid values use horizontal.
click()Activate a paired native anchor without writing history. Programmatic activation preserves visible focus.
ui-selectBubbling/composed, noncancelable selection event after actual change. See the guide for detail schema.
UI.enhance(root) / UI.destroy(root)Explicit structural refresh and scoped cleanup to readable sections. No Tabs-specific methods or properties.

Use the implemented tabs contract for the full integration rules and supported cases. Native attributes retain their standard meanings. Only ui-form and ui-error-summary register behavior.

Styles come from css/ui.css in the ui layer. Geometry and semantic colors use UI theme variables. Density and control sizes have separate scopes; they do not apply to every element.

Verification & known limits

Focused Tabs checks cover selection, keyboard ownership, fragments, nested form-error reveal, lifecycle and reflow. Real platform, assistive-technology, print and mobile/touch release evidence remains open; see ACCESSIBILITY.md.

Native/foundation is an implementation route, not a stable-release or accessibility certification. See dated results and unresolved findings; run the browser checks. Manual platform and assistive-technology verification remains part of release readiness.
