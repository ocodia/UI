Components / Helpers

Popover

native popover and popovertargetNative recipePhase 1

Reveal non-modal supporting content with the native popover API. The content determines its semantics; disclosure alone does not make it a menu.

Shared UI setup

Load js/ui.js once. Use the shared enhancement API for standard setup and scoped cleanup; application business rules remain separate.

Declarative native popover

One inline help copy becomes a native auto popover after successful installation. Buttons, keyboard traversal and dismissal stay native.

Full widthDrag the edge or use arrow keys; Shift changes by 50px. Home/End use minimum/full width.
Code
<script src="js/ui.js" defer></script>
<section>
  <h2>Project reference</h2>
  <p id="enhance-hint">Keep the original visit reference with your field notes.</p>
  <button id="enhance-open" type="button" popovertarget="enhance-help" hidden>Open reference help</button>
  <div id="enhance-help" data-ui="popover">
    <h3 tabindex="-1" data-ui-focus>Reference help</h3>
    <button type="button" popovertarget="enhance-help" popovertargetaction="hide" hidden>Close reference help</button>
    <p>Use the reference from the original visit record. A clear reference helps the coordinator match later observations without replacing earlier notes.</p>
    <h4>Keep useful context</h4>
    <p>Describe the route in ordinary words. Keep private contact details in a private channel. Editing this draft does not publish it or change project access.</p>
    <p><a href="../forms.html">Read the form integration guide</a>.</p>
    <button type="button" popovertarget="enhance-help" popovertargetaction="hide" hidden>Close reference help</button>
  </div>
  <label for="enhance-reference">Reference for the original coastal research visit</label>
  <input id="enhance-reference" name="reference" value="COAST-01" aria-describedby="enhance-hint">
</section>

Examples

Supplemental non-modal information

Native auto popover: Escape, outside activation and another auto popover can dismiss it. Background editing remains available. Without the page script or required native APIs, the complete help remains inline and the opener stays hidden. This is supplemental information with no menu or dialog role.

Full widthDrag the edge or use arrow keys; Shift changes by 50px. Home/End use minimum/full width.
Code
<script src="js/ui.js" defer></script>
<section>
  <h2>Project details</h2>
  <p id="title-hint">Use a short title and keep the original field notes. Optional help does not save or publish answers.</p>
  <button id="help-open" type="button" popovertarget="project-help" hidden>Open project help</button>
  <div id="help-inline">
    <h3>Choosing a project title</h3>
    <p>Choose a short, specific title that your team can recognise. Keep detailed observations in the field notes rather than in the title.</p>
    <p>Changing the title does not publish the project or change who can read it.</p>
    <p><a href="../forms.html">Read the form integration guide</a></p>
  </div>
  <div id="project-help" popover="auto" hidden>
    <button type="button" popovertarget="project-help" popovertargetaction="hide">Close project help</button>
    <h3>Choosing a project title</h3>
    <p>Choose a short, specific title that your team can recognise. Keep detailed observations in the field notes rather than in the title.</p>
    <p>Changing the title does not publish the project or change who can read it.</p>
    <p><a href="../forms.html">Read the form integration guide</a></p>
    <button type="button" popovertarget="project-help" popovertargetaction="hide">Close project help</button>
  </div>
  <ui-field><label for="project-title">Title for the coastal research project and its follow-up visits</label><input id="project-title" name="title" value="Coastal field guide" aria-describedby="title-hint"></ui-field>
  <ui-field><label for="project-reference">Project reference (optional)</label><input id="project-reference" name="reference" value="COAST-01"></ui-field>
</section>
<script>
(() => {
  const opener = document.querySelector('#help-open');
  const panel = document.querySelector('#project-help');
  const fallback = document.querySelector('#help-inline');
  const closers = panel ? [...panel.querySelectorAll('[popovertargetaction="hide"]')] : [];
  if (!opener || !panel || !fallback || !closers.length ||
      typeof panel.showPopover !== 'function' || typeof panel.hidePopover !== 'function' ||
      !('popoverTargetElement' in HTMLButtonElement.prototype) || panel.popover !== 'auto' ||
      opener.popoverTargetElement !== panel || closers.some(button => button.popoverTargetElement !== panel)) return;
  // Normalize pointer focus without replacing the native toggle action.
  opener.addEventListener('click', () => opener.focus());
  panel.hidden = false;
  fallback.hidden = true;
  opener.hidden = false;
})();
</script>

Keyboard, focus & native state

Native popovertarget supplies non-modal disclosure. Content keeps its own semantics; do not add a menu role. Check Escape, light dismissal, trigger focus and a useful inline fallback in the actual supported browser.

Values, validation & fallback

This primitive does not own application values, persistence or transport. Native descendants retain labels, values and form associations. Keep content readable before optional application behavior initializes.

Keep labels and instructions available when JavaScript fails. Applications own async work, recovery and server validation. Test disabled, invalid, long-content and loading states where the task supports them.

See the native family state audit for default, long-content, disabled/read-only, invalid, busy and fallback coverage, including states that do not apply.

API & styling

SurfaceContract
popoverNative auto/manual behavior. The example uses the default auto mode.
popovertargetTrigger button points to the popover ID.
popovertargetactionUse show, hide or toggle; toggle is the native default.
showPopover() / hidePopover() / togglePopover()Optional native imperative methods. Feature-detect before use.
beforetoggle / toggleNative state notifications. Semantics still follow the content.

Use the implemented popover contract for the full integration rules and supported cases. Native attributes retain their standard meanings. Only ui-form and ui-error-summary register behavior.

Styles come from css/ui.css in the ui layer. Geometry and semantic colors use UI theme variables. Density and control sizes have separate scopes; they do not apply to every element.

Verification & known limits

Browser assertions cover toggle/close, non-modal editing, native target relationships, focus restoration, disabled actions, auto-popover coordination, long-content bounds and missing-support/no-script fallback. Verify real Escape, light dismissal, keyboard traversal, zoom, mobile, forced colors and screen readers; see dated evidence in ACCESSIBILITY.md.

Native/foundation is an implementation route, not a stable-release or accessibility certification. See dated results and unresolved findings; run the browser checks. Manual platform and assistive-technology verification remains part of release readiness.
