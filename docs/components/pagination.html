Components / Navigation

Pagination

ui-pagination around a named native nav and list of linksFoundationPhase 2

CSS-only composition of a named native navigation list and real page URLs. Native current-page state, boundary omissions and wrapping; applications own result counts, routing, loading and focus after updates. See docs/pagination.md.

Implementation maturity: experimental. See dated evidence and remaining release gates.

Read the component specification and its Markdown source.

Examples

Report pages: 1 of 5

Links open separate static pages with different results. They work without JavaScript.

Full widthDrag the edge or use arrow keys; Shift changes by 50px. Home/End use minimum/full width.
Code
<link rel="stylesheet" href="css/ui.css">
<section aria-labelledby="reports">
  <h2 id="reports" tabindex="-1">Reports: page 1 of 5</h2>
  <p>Showing 1–2 of 10 reports.</p>
  <ul><li>Coastal bird survey</li><li>Estuary water quality</li></ul>
  <ui-pagination>
    <nav aria-label="Report pages">
      <ul role="list">
      <li><a href="pagination-0.html#reports" aria-label="Page 1" aria-current="page">1</a></li>
      <li><a href="pagination-1.html#reports" aria-label="Page 2">2</a></li>
      <li><span>…</span></li>
      <li><a href="pagination-4.html#reports" aria-label="Page 5">5</a></li>
      <li><a href="pagination-1.html#reports" rel="next">Next</a></li>
      </ul>
    </nav>
  </ui-pagination>
</section>

Keyboard, focus & native state

Named native nav, list and real anchors. Tab/Shift+Tab and Enter remain native; no arrow-key handler, roving focus or custom role. aria-current=page marks one current link.

Values, validation & fallback

CSS-only ui-pagination scopes wrapping and current-page presentation. Omit unavailable previous/next links; ellipses are text. Applications own URLs, totals, async loading and focus after updates.

Keep labels and instructions available when JavaScript fails. Applications own async work, recovery and server validation. Test disabled, invalid, long-content and loading states where the task supports them.

API & styling

SurfaceContract
ui-paginationCSS-only composition boundary around one named native nav and ul/ol.
href / relReal native destinations; optional prev/next relationships. Preserve filters and sort state in URLs.
aria-current=pageAuthored current location on one real link; UI does not calculate or rewrite it.
Native listUse li children and role=list when removing list markers. Omit unavailable boundary links; ellipses are text.

Use the implemented pagination contract for the full integration rules and supported cases. Native attributes retain their standard meanings. Only ui-form and ui-error-summary register behavior.

Styles come from css/ui.css in the ui layer. Geometry and semantic colors use UI theme variables. Density and control sizes have separate scopes; they do not apply to every element.

Verification & known limits

Verify real destination navigation, current-page uniqueness, previous/next boundaries, plain-text ellipses, native focus/keyboard ownership and no-script navigation. Focused evidence and remaining platform checks are recorded in ACCESSIBILITY.md.

Native/foundation is an implementation route, not a stable-release or accessibility certification. See dated results and unresolved findings; run the browser checks. Manual platform and assistive-technology verification remains part of release readiness.
