Project details

Use a short title and keep the original field notes. Optional help does not save or publish answers.

Preparing a useful project description

Keep the title short enough to recognise in a project list. Put the full context in the description and use field notes for observations from individual visits. A descriptive title helps people find the right project without needing an internal code.

Explain the purpose

Describe the question the team is exploring and the places involved. Use ordinary words and explain unfamiliar terms the first time you use them. Separate confirmed observations from ideas that still need checking.

If plans change, update the description and leave enough context for someone who was not at the meeting. You can keep existing notes while reviewing a new route or preparing a later visit.

Keep private information separate

Do not include private contact details in the project title or general description. Ask before sharing photographs or recordings of other people. Project access and publication are separate application decisions; editing a title does not make a project public.

Use a private channel for arrangements that only the coordinator needs. Describe access needs without making assumptions about another person or recording more information than the task requires.

Make the next step clear

Explain what someone can contribute now: review an observation, suggest a route or prepare equipment for a visit. Keep a readable version of the arrangements available when a device or connection is unavailable.

Give each action a clear destination or label. Keep important instructions beside the task rather than only inside this optional help. You can close the help at either end, return to editing and reopen it when needed.
