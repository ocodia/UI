Accessible form conventions

Native labels and controls stay in the HTML. UI elements group the question, hint, and error. Keyboard focus stays visible across themes.

There is a problem

     Use a short name that helps you recognise the project. Error: Enter a project name 
    <ui-field>
  <label for="name">Project name</label>
  <ui-hint id="name-hint">Use a short name.</ui-hint>
  <input id="name" aria-describedby="name-hint">
</ui-field>

    ui-form coordinates validation, hints, inline errors, and focus. The native form still owns its controls and submission.

    <ui-form>
  <form action="/projects" method="post">
    <ui-field>…native label and input…</ui-field>
    <button>Save project</button>
  </form>
</ui-form>

    Try submitting the workspace with an empty project name to see linked errors and focus movement.

    Themes and customization

    UI follows your system theme automatically. This page can also preview a forced light or dark theme.

    Override a few CSS variables in your own stylesheet to set your brand and spacing.

    :root {
  --ui-action-bg: #005cc5;
  --ui-action-text: #fff;
  --ui-radius: .5rem;
  --ui-content-width: 72rem;
}

    Use your browser’s print preview to see the print styles. UI adds no decorative motion.
